# rusty messenger

Краткое описание:

**Высоконагруженный мессенджер на Rust** - учебный проект, создаваемый для глубокого изучения современного стека бэкенд-разработки. Проект демонстрирует применение лучших практик: чистая архитектура, dependency injection, асинхронность, безопасное хранение паролей, JWT-аутентификация и контейнеризация.

    **Учебный проект (в разработке)** - функциональное ядро готово, добавляются новые возможности.

## Технологический стек
    - Язык: Rust (edition 2024)
    - Веб-фреймворк: Axum
    - База данных: PostgreSQL (драйвер SQLx)
    - Асинхронность: Tokio
    - Логирование: Tracing + Tower HTTP
    - Конфигурация: Clap + dotenvy
    - Контейнеризация: Docker (multi-stage build)
    - Оркестрация: Docker Compose
    - Хеширование паролей: Argon2id
    - JWT аутентификация: jsonwebtoken
    - Сериализация: Serde + Serde JSON

## Возможности на данный момент

### Аутентификация и безопасность
    - **Регистрация пользователей** (`POST /users`) - создание нового пользователя с хешированием пароля через Argon2id (OWASP-рекомендации).
    - **Вход в систему** (`POST /auth/login`) - проверка email и пароля, выдача JWT-токена (срок действия: 24 часа).
    - **JWT-аутентификация** - токен подписывается с использованием HS256, содержит идентификатор пользователя и время истечения.
    - **Безопасное хеширование** - пароли никогда не хранятся в открытом виде, используется криптографически стойкая соль.

### HTTP-эндпоинты
    - Метод: 'GET', путь: /health - Проверка работоспособности сервера (возвращает 'OK')
    - Метод: 'POST', путь: /users - Регистрация нового пользователя (принимает JSON с 'username', 'email', 'password')
    - Метод: 'POST', путь: /auth/login - Аутентификация пользователя (принимает JSON с 'email', 'password', возвращает JWT-токен)

### База данных
    - **Схема подготовлена** для:
        - Пользователей ('users') - id, username, email, password_hash, created_at.
        - Чатов ('chats') - id, name, is_group, created_at.
        - Участников чатов ('chat_members') - chat_id, user_id, role, joined_at.
        - Сообщений ('messages') - id, chat_id, sender_id, content, created_at.
    - **Миграции** - управляются через SQLx (папка 'migrations/').

### Логирование и наблюдаемость
    - **Структурированные логи** через 'tracing'.
    - **Автоматическое логирование HTTP-запросов** через 'TraceLayer' (Tower).
    - **Логирование ошибок БД** с деталями для отладки.

### Контейнеризация
    - **Dockerfile** с многостадийной сборкой (Rust -> минимальный Debian).
    - **Docker Compose** для локальной разработки с PostgreSQL.
    - **Offline-режим SQLx** для сборки без подключения к БД (переменная 'SQLX_OFFLINE=true').
